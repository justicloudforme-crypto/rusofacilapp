# Смена ключей Stripe — пошаговая инструкция для владельца (долг 401, заход 7.316, 27.11.2026)

**Для кого:** владелец сайта, без программирования. Всё делается в браузере, в двух панелях: Stripe и Vercel.
**Сколько времени:** 20–30 минут, из них ≈10 минут — ждать, пока Vercel пересоберёт сайт.
**Зачем:** после письма Stripe от 22.10.2026 («Your Node.js version may be vulnerable») решено сменить секретные ключи —
на случай, если старые кто-то видел. Следов взлома не найдено; это мера предосторожности.

**Что меняется — ровно два значения:**

| что | имя переменной в Vercel | как выглядит начало | где взять в Stripe |
|---|---|---|---|
| секретный ключ | `STRIPE_SECRET_KEY` | `sk_live_…` | Developers → API keys → Secret key |
| секрет вебхука | `STRIPE_WEBHOOK_SECRET` | `whsec_…` | Developers → Webhooks → наш адрес → Signing secret |

**Что НЕ трогать:** `STRIPE_PUBLISHABLE_KEY` (`pk_live_…` — он публичный, его и так видит каждый браузер),
`STRIPE_PRICE_MONTHLY` / `STRIPE_PRICE_ANNUAL` / `STRIPE_PRICE_LIFETIME` (это номера цен, не ключи), всё остальное в Vercel.
Цены, подписки и покупатели в Stripe от смены ключей не меняются. Оплата в приложении (Google Play / RevenueCat) — не связана.

**Самих ключей никому не пересылать** — ни агенту, ни в чат, ни в почту. Их видят только Stripe и Vercel.

**Защита от ошибки уже встроена.** Если вставить в Vercel не то (например, `pk_…` вместо `sk_…` или ключ с пробелом),
сборка сайта сама откажется (`scripts/check-stripe-env-shape.ts`), а живой сайт останется на старой сборке со старыми
ключами — сломанный ключ до покупателей не дойдёт. Поэтому порядок ниже безопасен: старые ключи работают ещё 24 часа.

---

## Шаг 1. Новый секретный ключ в Stripe

1. Откройте https://dashboard.stripe.com/apikeys (войти в Stripe, если попросит).
2. Убедитесь, что вверху **не** включён «Test mode» / «Sandbox» — нужен боевой режим (Live).
3. В блоке **Standard keys** найдите строку **Secret key** (`sk_live_…`).
4. Справа нажмите **⋯** → **Roll key…** (по-русски может быть «Сменить ключ»).
5. В окне выберите, когда отключить старый ключ: **in 24 hours** («через 24 часа»). Так сайт не прервётся,
   пока вы вставляете новый ключ в Vercel и сайт пересобирается.
6. Нажмите **Roll API key**. Stripe может попросить код из письма или телефона — введите.
7. Stripe покажет **новый ключ один раз**. Нажмите на него, чтобы скопировать. Он начинается с `sk_live_`.
   **Не закрывайте это окно**, пока не вставите ключ в Vercel (шаг 2). Если окно закрылось — ключ больше не показать,
   повторите шаг 1 (это не страшно, старый ключ всё равно работает 24 часа).

> Не создавайте «Restricted key» (`rk_live_…`) — сайт ждёт именно `sk_live_…`, иначе сборка откажется.

## Шаг 2. Вставить секретный ключ в Vercel

1. Откройте https://vercel.com → проект сайта **rusofacilapp** → вкладка **Settings** → слева **Environment Variables**.
2. В поиске по переменным наберите `STRIPE_SECRET_KEY`.
3. Справа от неё **⋯** → **Edit**.
4. Сотрите старое значение и вставьте новое (Cmd+V). Проверьте: в начале `sk_live_`, в конце нет пробела.
5. Окружения (галочки Production / Preview / Development) **оставьте как были** — не меняйте.
6. Нажмите **Save**.

## Шаг 3. Новый секрет вебхука в Stripe

Вебхук — это адрес, по которому Stripe сообщает сайту «оплата прошла», «подписка отменена».

1. Откройте https://dashboard.stripe.com/webhooks (боевой режим, как в шаге 1).
2. Нажмите на адрес **https://rusofacilapp.com/api/webhooks/stripe**.
3. Найдите блок **Signing secret** → **⋯** (или кнопка рядом) → **Roll secret…**.
4. Срок отключения старого секрета — **24 hours** (максимум). В эти сутки Stripe подписывает сообщения и старым, и новым
   секретом, поэтому ни одно сообщение об оплате не потеряется.
5. Нажмите **Roll secret**, затем **Reveal** и скопируйте новый секрет. Он начинается с `whsec_`.

## Шаг 4. Вставить секрет вебхука в Vercel

Как в шаге 2, только переменная **`STRIPE_WEBHOOK_SECRET`**: ⋯ → Edit → вставить `whsec_…` → окружения как были → **Save**.

## Шаг 5. Пересобрать сайт

Новые значения начинают работать только после новой сборки.

1. В Vercel откройте вкладку **Deployments** проекта.
2. Самая верхняя строка с пометкой **Production** и **Current** — это живой сайт. Справа **⋯** → **Redeploy**.
3. В окне ничего не меняйте и нажмите **Redeploy**.
4. Подождите ≈10 минут, пока у новой строки появится зелёное **Ready**.
   * **Ready** — всё хорошо, переходите к шагу 6.
   * **Error** — сборка отказалась: скорее всего, скопирован не тот ключ или с лишним символом. Живой сайт при этом
     продолжает работать на старой сборке. Повторите шаг 2 или 4 и снова Redeploy. Если не получается — напишите агенту,
     что сборка упала (без ключей).

> Если в этот момент ждёт мержа PR сайта, можно вместо Redeploy просто смержить его: выкат после мержа тоже
> подхватит новые ключи. Главное — сначала сохранить ключи в Vercel (шаги 2 и 4), потом мержить.

## Шаг 6. Сказать агенту

Напишите в окне агента: **«ключи поменял»**. Агент проверит:

* новая сборка Vercel — **Ready**, живой сайт отвечает этой сборкой;
* проверка GitHub «Прод после выката» по этому выкату — зелёная;
* страницы цен `/es/pricing` и `/ru/pricing` открываются с ценами;
* оформление покупки открывается: тестовым аккаунтом сайт выдаёт страницу оплаты Stripe (оплату агент **не** проводит);
* сторож цен Stripe (раз в час проверяет ключом, что цены живые) не поднял тревогу.

**Что агент проверить не может — посмотрите сами (2 минуты):**

1. **Sentry** (https://sentry.io → проект сайта → Issues): за время после Redeploy нет новых ошибок со словом
   `Stripe` (например, `StripeAuthenticationError`, `Stripe price health`, `StripeEnvWrongShape`).
2. **Stripe → Webhooks → наш адрес → Event deliveries**: последние события — с зелёным **200**. Если покупок после
   смены ещё не было, нажмите **Send test event** (любое событие) — ответ должен быть **200** (`received: true`).
   Ответ **400** с текстом про подпись («No signatures found matching…») значит, что в `STRIPE_WEBHOOK_SECRET`
   вставлено не то — повторите шаг 4 и Redeploy.
3. Можно открыть, будучи вошедшим на сайт под своим аккаунтом администратора:
   https://rusofacilapp.com/api/admin/stripe-health — все три цены должны быть **OK** (эта страница ходит в Stripe
   новым ключом).

## Шаг 7. Когда отключится старый ключ

**Ничего делать не нужно:** старый секретный ключ и старый секрет вебхука отключатся сами через 24 часа после шагов 1 и 3.
Если агент после «ключи поменял» нашёл проблему — у вас есть эти 24 часа, чтобы поправить значение в Vercel, и покупатели
ничего не заметят.

Если хочется отключить старый ключ раньше (после зелёной проверки агента): Stripe → API keys → у старого ключа
(с пометкой «Expires …») **⋯** → **Expire key now**.

## Что ещё знать

* На Маке в локальном файле `.env` лежат старые ключи; после отключения они перестанут работать — это нормально, оплату
  на Маке не проводят (правило проекта). Менять там ничего не нужно.
* В GitHub ключей Stripe нет — там менять нечего.
* Агент сам ключи не меняет и в панели Stripe и Vercel не заходит (решение владельца 7.316).
