# Паспорт озвучки нового контента

**Читать до того, как завести новый рассказ, урок, карточку, идиому,
медиа-страницу, термин глоссария, слово для тапа или пару синонимов и
антонимов.** Документ отвечает на один вопрос: *что нужно сделать, чтобы
новый контент зазвучал, и чем доказывается, что он зазвучал.*

## 0. Золотое правило

**Звучит только оплаченная записанная озвучка. Голоса, синтезированного
на лету, — в том числе браузерного `speechSynthesis` — в продукте нет
нигде.** Правило владельца, зафиксировано в `CLAUDE.md`, коммит `741ae51`.

Из него следуют три вещи, и все три проверяемы:

1. Синтез бывает **один раз и навсегда**, серверным скриптом, а результат
   лежит строкой в `AudioAsset` и файлом в Blob. Пересинтез уже
   озвученного текста — трата денег владельца; повторно синтезировать
   можно только то, что аудит отверг, и **ровно один раз** (вывод 7.165).
2. Орган управления «слушать» без записи **не подменяется ничем**: он
   остаётся на месте, приглушается после гидрации и молчит. Это не
   недоделка, а решение: чужое произношение хуже тишины (7.160, долг 114).
3. Браузерного синтеза нет в коде. Держит сторож `check:no-runtime-tts`:
   ни `speechSynthesis`, ни `SpeechSynthesisUtterance` — ни в исходниках
   продукта, ни в собранных клиентских бандлах.

## 1. Параметры банка — одни на весь проект

| | |
| --- | --- |
| модель | `gpt-4o-mini-tts` |
| голос | `onyx` (мужской; кроме озвучки рассказов — см. ниже) |
| формат | mp3 |
| знак ударения в тексте синтеза | **не ставится** (проверено и отвергнуто числом в 7.165: помогает не он, а простой пересинтез) |
| хранение | строка `AudioAsset` + объект в Blob-хранилище `AUDIO_BLOB_STORE_ID` |
| ключ строки | `(contentType, contentId, itemKey)` — уникален |
| `text` | текст, **уже пропущенный** через `sanitizeTextForTTS` (`src/lib/speech.ts`) |
| `textHash` | sha256 того же текста |

Исключение ровно одно: **озвучка самих рассказов** идёт кастом из пяти
голосов (`generate-story-audio-cast.ts`), поэтому клип рассказа никогда не
переиспользуется для кнопок других поверхностей — иначе женский голос
уехал бы в урок. Запрет живёт в `pickReusableClips`
(`src/lib/audio-reuse-pick.ts`) и стережётся подсадкой.

## 2. Прежде чем синтезировать — поискать оплаченное

Новый текст очень часто уже озвучен рядом: в 7.163 из 2128 кнопок без
записи **1031** оказалась с уже оплаченным клипом того же текста. Порядок
поиска клипа — один на весь продукт и живёт в двух чистых модулях, чтобы
и продукт, и сторожа считали ОДНИМ кодом (класс долга 104):

* `src/lib/lessons/audioKeys.ts` — `pickClip`: позиционный ключ →
  сырой текст → очищенный текст (третья ступень заведена в 7.166, долг 125:
  `AudioAsset.text` хранится очищенным, а кнопка спрашивает сырым);
* `src/lib/audio-reuse-pick.ts` — `pickReusableClips`: выбор чужого
  оплаченного клипа по тексту, детерминированный по
  `(contentType, contentId, itemKey)`;
* `src/lib/story-word-pick.ts` — `pickWordClip` (слово рассказа) и
  `pickStoryWordClip` (вырезка омографа по месту).

разметке обязан быть настоящий `<audio>`.

## 4. Пары синонимов и антонимов

Своей озвучки **не имеют и не должны иметь**: это те же слова словаря, и
у каждого уже есть свой клип карточки. Отдельная кнопка на паре не
рисуется — блок 7.167 выводит их обычным текстом. Если кнопка там
появится, `check:listen-buttons` увидит новую поверхность без
закреплённого числа и упадёт.

## 5. Аудит: что машина проверяет и чего не может

Аудит расшифровывает свежий клип и сверяет с текстом. Он отвечает на один
вопрос — **то ли слово звучит**. Верное ли в клипе **ударение**, он не
слышит вовсе; это слышно только ухом.

Правила аудита, выведенные числом, а не мнением:

* короткие клипы для расшифровки **утраиваются** — на однословных клипах
  распознаватель иначе ошибается (7.165). Для **вырезок** это правило
  НЕ действует и проверено обратным: 7.168 прогнал утроение на 46
  одобренных ухом вырезках и получил 18 из 46 — склейка сама рождает
  слоговые химеры;
* имя промежуточного файла — **по sha256 полного пути**, а не по слову:
  `\w` в JavaScript кириллицу не покрывает, и «своей.mp3» с «долго.mp3»
  схлопывались в один файл, а распознавателю уходил клип чужого слова
  (7.166, 116 выброшенных замеров);
* отвергнутое пересинтезируется **ровно один раз** и без знака ударения;
  не принятое и со второго раза уходит владельцу на слух, а не на третий
  круг;
* мера «чистые края» (тишина по краям вырезки) **негодна** и отвергнута
  числом: у слова внутри связной речи тишины по краям не бывает (7.166,
  13 верных вырезок из 17 отвергнуты ею напрасно).

## 6. Прослушивание владельцем — обязательный шаг

**Ни один клип не уезжает на прод без слуха владельца, если аудит его не
принял, и ни одна вырезка омографа — вообще никогда.** Порядок:

1. клипы складываются в `~/rusofacil-listen/<заход>/на-слух/` **вне
   репозитория**;
2. рядом `список.txt`: файл, слово, что услышал распознаватель, уровень,
   сколько мест затрагивает;
3. отдельно `выборка/` — уже записанные клипы для проверки ударения
   ухом;
4. владелец слушает и говорит «да»; только после этого — запись на прод
   и **без нового синтеза**, файлы уже оплачены.

## 7. Запись на прод — порядок, от которого не отступают

1. снимок всех строк `AudioAsset` до записи + sha256-отпечаток пар
   `(id, audioUrl)`;
2. **сухой прогон** (`--dry-run`): план, занятые ключи, занятые пути Blob;
3. обкатка `--only=5`;
4. запись; `allowOverwrite: false` — занятый путь это **отказ**, а не
   тихая перезапись. **`--force` не применяется никогда**;
5. доказательство: у каждого нового адреса HTTP 200, ожидаемый
   `Content-Type` и размер ответа, совпавший с локальным файлом **до
   байта**;
6. отпечаток ПРЕЖНИХ строк после записи обязан совпасть с отпечатком до
   знак в знак;
7. журнал записи (`written.jsonl`) и снимок «до» остаются в папке
   владельца — это и есть откат.

## 8. Заморозка

До 26.09.2026 серверный HTML 330 URL (`docs/frozen-baseline-2026-08-30.json`)
не имеет права сдвинуться. Поэтому:

* клип, который попал бы в серверный HTML замороженной страницы, **не
  записывается** (так живут три слова со `song-katyusha` — «груша»,
  «расцветать», «яблоня»);
* клип для тапа по слову ищется адресом `/api/word-audio`, а не через
  разметку, — именно поэтому банк из 12 052 слов не сдвинул заморозку ни
  на знак;
* до и после любой записи гоняется `npm run check:frozen` и снимаются
  330 URL с живого прода.

## 9. Проверки, которые обязан пройти новый контент

| проверка | что держит |
| --- | --- |
| `npm run check:no-runtime-tts` (+ `:plant`, `:bundles`) | браузерного синтеза нет ни в исходниках, ни в бандлах |
| `npm run check:listen-buttons` | перепись всех органов «слушать» по боевой базе; новая поверхность без закреплённого числа — падение |
| `npm run check:listen-buttons:plant` | правило выбора клипа, 24 подсадки |
| `npm run check:silent-listen:plant` | орган «слушать» без настоящего `<audio>` в разметке |
| `npm run check:audio-passport` (+ `:plant`) | этот документ описывает КАЖДУЮ поверхность со звуком |
| `npm run check:story-audio` | у рассказа озвучено каждое предложение |
| `npm run check:frozen` | 330 замороженных URL не сдвинулись |

## 10. Исключения

Поверхность может стоять в списке исключений `check:audio-passport`
только вместе с причиной. Сегодня исключений **нет**.
