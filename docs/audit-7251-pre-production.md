### 2.2. «▶ начинает с первой фразы, полоска прыгает в ноль» (видео владельца 30.09, POCO, с сетью)

**Как задумано.** С 7.240 возврат на рассказ **продолжает с сохранённой строки**: `handlePlayPause` (`src/components/stories/StoryText.tsx:877–890`) при `readingQueueIndex === null`, `resumeQueueIndex !== null` и `audio.currentTime === 0` ставит `currentTime = sentenceOffsets[resumeQueueIndex]`. Полоска при возврате показывает то же сохранённое место (`displayQueueIndex`, `:1177`). Обнуление в 7.248 касается **только шкалы шторки** (плагин), не места чтения. Значит, «с первой фразы» — **расхождение, а не замысел**.

**Замер на эмуляторе (живая страница, дорожка из сети):**

| путь | полоска после возврата | «▶» | итог |
|---|---|---|---|
| 20 с → «Vocabulario» → «Cuentos» → «Репка» | 57,1 % (строка 8 из 14) | `currentTime = 35,45` → 35,6 · 36,6 · 37,6 · 38,6, полоска 57 → 64 % | продолжает с места |
| → «Juegos» → «Назад» Android | 85,7 % (строка 12) | 66,6 → 69,8 | продолжает с места |
| настольный Chromium, 3-й заход | — | 7,6 → 8,5 → 9,5 … | продолжает с места |

**Что воспроизводит «с начала» и где:**

1. **Сохранённая копия** (`public/offline.html` = `capacitor-shell/offline.html`, `armStoryPlayer`): `state.index = -1`, «▶» → `playAt(Math.max(0, state.index))` = фраза 0; `rusofacil:story-progress` копия не читает. Замер: сохранено `queueIndex 12`, полоска копии 0 %, через 3 с после «▶» подсвечена вторая фраза. Но полоска копии «прошлого места» не показывает — картинка с видео (≈¼ и ≈¾ до «▶») с копией **не совпадает**. Долг 363.
2. **Дорожка из кеша воркера на первом заходе после кеширования** — `MediaError`. Настольный Chromium 151, два прогона по 8 и 3 захода: заход 1 (воркера ещё нет) играет; **заход 2 (воркер есть, дорожка только что легла в `rf-audio`) — `error.code 2`, `currentTime` стоит**; заходы 3–8 играют с сохранённого места. Сценарий владельца «прослушал часть → ушёл → вернулся → ▶» — это и есть заход 2: в Chromium после возврата `17,1 E2 paused`, три нажатия «▶» не помогают. На эмуляторе (WebView 133) сбой на каждой загрузке через воркер (`E2`, после перезагрузки `E4 Format error`), а тот же файл мимо воркера (`?nosw=7251`) и тот же байт-в-байт blob из `rf-audio` играют (3,64 из 89,208 с). Файл на сервере исправен (200, `Range` → 206). Запрос `Range: bytes=0-` воркер отвечает **200 целиком** вместо 206.
