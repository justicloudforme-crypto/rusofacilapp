## Дизайн-система (закрыто)

**Направление — «Кремль»** (вариант C из трёх предложенных), с тёплой
поправкой: глубокий индиго-синий primary + тёплые (не холодные) нейтрали +
золото только для некликабельных маркеров.

- **primary** — `#253B7E` (indigo, hue 225°). Это НЕ исходный `#2D5F8A` —
  сознательно углублён по вашему запросу (кандидат 3 из 3 предложенных,
  с реальным сдвигом оттенка, не просто темнее). Единственный кликабельный
  акцент во всём приложении: все кнопки, ссылки, активные состояния,
  включая CTA тарифа Lifetime на /pricing.
- **premium** — золото (`#CE9627` и шкала), **строго некликабельный**
  маркер ценности: крон-бейдж, карточка Premium/Lifetime, награды,
  огонёк стрика. Никогда не кнопка, никогда не ссылка. В тёмной теме
  primary-текст на прямом фоне (не в кнопке) использует отдельный алиас
  `primary.darkText` (`#7087CD`) — сам primary-600 «тонет» на тёмном фоне
  (1.74:1), это была реальная проверенная проблема, не гипотеза.
- **neutral** — тёплая кремовая шкала (не холодный графит), systematized
  из старых разрозненных `#f6efdc`/`#fff8ec`/`#1b140f`.
- **folk-red vs danger** — важное разделение: старый `--brand-accent`
  (красный) НЕ стал слепо «danger». 19 из 21 реальных использований были
  декоративными/позитивными (конфетти, огонёк стрика, карточка стрика,
  бейдж «Популярный» на /pricing, победные анимации) → отдельный токен
  `folk-red` (тот же hex, другое имя, чтобы будущая правка danger не
  перекрасила конфетти). Только 2 места (сообщения об ошибке на
  login/register) — настоящий `danger`.
- **Кнопка «Выйти»** в мобильном меню — нейтральная (не folk-red, не
  danger) — это обычное действие.

### Что защищает правила
`npm run check:tokens` (`scripts/check-tokens.mjs`) — два независимых
гварда, падает с ненулевым кодом при нарушении:
1. **Контраст** — пересчитывает WCAG-контраст для списка задокументированных
   пар текст/фон (primary/neutral/premium/danger/success/warning/уровни
   A1-C1, включая тёмную тему) и требует ≥4.5:1 (или явно ожидает провал
   там, где это демонстрация проблемы).
2. **Premium-на-кликабельном** — ищет `bg-premium`/`text-premium`/
   `border-premium`/`var(--color-premium` на одной строке с
   `onClick=`/`onPress=`/`href=`/`<Button` и падает при совпадении.

Сейчас: **15/15 контраст-пар проходят, 0 нарушений premium**.

### Источник правды
- **`tokens.json`** (корень репозитория) — платформонезависимый источник:
  цвета (со шкалами и обоснованием каждого шага), типографика (fluid
  clamp() в rem), отступы (кратны 4px), радиусы, тени, длительности,
  и таблица `migration` — куда делось каждое старое значение.
- **`scripts/build-tokens.mjs`** генерирует `src/app/tokens.generated.css`
  (CSS-переменные + `@theme inline` — это и есть Tailwind-конфиг проекта,
  отдельного `tailwind.config.ts` нет и не создавался, Tailwind v4 на
  CSS-конфиге).
- **`/[lang]/styleguide`** (`noindex`, есть переключатель темы) — живая
  галерея всех компонентов и палитры, включая блок «Не так / так» для
  правила premium.

## Открытые вопросы и отложенное

- **Дневная цель в хедере** — метрики в коде нет (только streak,
  `getUserStreakStats`), продуктовое решение, что считать «целью», не
  принято. Сознательно НЕ придумывал фейковую метрику.
- **Полнотекстовый поиск по контенту** — Cmd+K сейчас закрыт по объёму
  до статичных разделов навигации (`GlobalSearch.tsx`). Нужен ли единый
  search-API по историям/глоссарию/урокам — не решено, это новая
  бизнес-логика (агрегирующий API-роут к БД), не навигационный слой.
- **Языковой разрыв в /ru** — описания рассказов на испанском и подсказки
  кроссворда на испанском в русской локали. Подтверждено в AUDIT.md: это
  **проблема данных** (в БД/статичных файлах нет русского текста), а не
  отсутствующего перевода в коде. Не чинить в UI-шагах, отдельная
  контентная задача.
- **~76 файлов с сырым `<button>`** вне компонента `Button`, плюс
  Input/Select ещё не подключены к формам (login/register/groups/поиск/
  crossword-инпут) — полный список в AUDIT.md §11. Правило: мигрировать
  файл при следующем содержательном касании, не отдельным проходом.
- **Цены в Stripe** — владелец меняет отдельно, не через эту работу.
- ~~**Остальные даты на /profile ещё в серверной таймзоне**~~ — закрыто
  в шаге 9 (`27f5518`): все `dateFormatter.format()` на /profile теперь
  `<LocalDate>`.
- **Пробный период (7 дней) не реализован** — требует правок
  checkout/webhook-логики (Stripe `trial_period_days` на подписке), вне
  скоупа UI-редизайна /pricing. Для нового продукта триал заметно
  поднимает конверсию — вернуться к этому отдельной задачей, когда
  можно трогать checkout.
- ~~**Цена Premium: MXN/USD рассинхрон**~~ — закрыто: владелец подтвердил
  финальную цену $122.99 USD (Stripe меняет сам), долларовая цена на
  странице обновлена под неё, теперь сходится с MXN (2299 при курсе
  ~18.7, как и у monthly/annual).
- **Гарантия возврата — ручная политика, не Stripe-автоматизация**
  — 14-дневный возврат на /pricing и в FAQ /pricing — это текст
  обязательства, реальный возврат оформляется вручную через
  Stripe-дашборд по обращению на support@rusofacilapp.com. В коде
  нет автоматического возврата.
- **Налоги в FAQ /pricing** — ответ «цена окончательная, налоги
  включены» дан по прямому подтверждению пользователя, что это верно
  для текущей настройки Stripe; в коде нет проверяемой Stripe Tax
  конфигурации, сам я это установить не мог.

## Правила работы (полный текст — в CLAUDE.md)

- Mobile-first: любой макет сначала на 375px, потом 768px, 1280px.
- Все стили — только через дизайн-токены, никаких новых хардкод-цветов/
  теней/радиусов на местах.
- **primary** — единственный кликабельный акцент. **premium** — только
  некликабельные маркеры ценности (enforced by `check:tokens`).
- Минимальный тач-таргет 44×44px, hover не существует как класс
  взаимодействия на мобиле — везде нужен явный tap-отклик.
- Capacitor подтверждён (не гипотетический) — `viewport-fit=cover` +
  safe-area-inset на всех фиксированных элементах, `100dvh` не `100vh`,
  никакого `position:fixed` на полях ввода, обработка аппаратной кнопки
  «Назад» уже есть (`NativeBackButtonHandler.tsx`).
- Не трогать бизнес-логику, роутинг, Stripe-интеграцию без явной просьбы.
- План и остановка перед крупными структурными изменениями.
- Каждый шаг — отдельный коммит, с возможностью отката одной командой.
- После каждого шага — проверка check:tokens/lint/typecheck/build, и
  затем **живая проверка на телефоне** пользователем, прежде чем идти
  дальше.

Полные обоснования и file:line-ссылки на всё перечисленное — в AUDIT.md
(текущая база багов/несоответствий) и CLAUDE.md (правила проекта).
